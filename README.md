# FffTV

邀请制的小型影视放映室。使用 Next.js 16、React 19、Node.js 24 内置 SQLite 和 HLS.js。

## 本地启动

```sh
npm install
npm run setup
npm run dev
```

访问 http://127.0.0.1:3000 。首次运行 `setup` 会在本地生成 `.env.local`，用户名为 `admin`，随机密码保存在该文件中。脚本不会覆盖已有配置，也不会把密码打印到日志里。首次访问时初始化数据库及管理员。

`ADMIN_PASSWORD` 仅用于首次创建管理员，修改环境变量不会修改已有账号。密码至少 12 位；成员密码至少 8 位。当前版本尚未提供密码重置界面。

## 当前功能

- 邀请码注册、登录、退出；HttpOnly 会话、scrypt 密码散列、一次性邀请码。
- 多来源搜索、响应超时、搜索缓存和部分来源失败提示。
- 作品详情、选集、HLS/MP4 播放、浏览器原生控制、自动下一集、重试和手动换源。
- 每用户收藏和观看进度；默认每 10 秒、暂停、页面隐藏时保存。
- 管理员生成邀请码、查看成员、启停内置来源。
- 桌面与移动布局，海报失败时使用本地样式占位，外部简介只以文本渲染。

作品用规范化片名及年份形成内部标识，数字集号用于跨来源匹配；片库合并时同时区分内容类别。用户主动切换来源时可沿用已有记录，但不会猜测缺失剧集。新番目录使用 Bangumi 条目 ID，播放源仍按片名、年份和别名匹配。

内置来源来自 `diagnostics/source-verification-2026-11-10.md` 的技术调研，默认启用魔都、极速、360，其他候选可在管理页开启。候选接口的技术可用性不代表取得内容授权。来源定义在 `src/lib/catalog.ts`，仅管理员可启停；不接受访客传入任意代理地址。生产使用前需确认内容使用权限。

## 配置与部署

| 配置                            | 含义                                                     |
| ------------------------------- | -------------------------------------------------------- |
| ADMIN_USERNAME / ADMIN_PASSWORD | 首次管理员凭据                                           |
| DATABASE_PATH                   | SQLite 路径，默认 `./data/ffftv.sqlite`                  |
| APP_ORIGIN                      | 网站的准确访问 Origin，POST 请求严格匹配，包含非默认端口 |
| COOKIE_SECURE                   | HTTPS 部署设为 `true`，本地 HTTP 为 `false`              |

```sh
npm run build
npm start
# 或
docker compose up -d --build
```

Docker Compose 将服务绑定在本机 3000 端口，可由 HTTPS 反向代理转发。上线前设置真实 `APP_ORIGIN` 和 `COOKIE_SECURE=true`，重启服务。保留 `ffftv-data` 卷。单实例部署，不要在 Vercel 等临时文件系统上保存 SQLite。备份需使用 SQLite 一致性备份，或停止服务后一并复制数据库及 WAL 文件。

视频由浏览器直接连接来源，服务器只读取固定来源及 Bangumi 的目录接口。部分来源跨域、防盗链、编码或网络不兼容时需要换源；当前不包含媒体代理、DRM、字幕转码或带宽优化。新部署地区需要重新测试实际播放。首页展示季度首播名单，片库的收录和搜索能力见下文。

## 验证

```sh
npm run typecheck
npm test
npm run build
# 网站已启动且 .env.local 已初始化后，运行真实接口与账号流程检查
npm run test:smoke
```

测试覆盖来源解析、剧集匹配、低质量播放项排序、私网地址拒绝、密码散列、邀请原子消费、会话失效及用户数据隔离。

`test:smoke` 会创建临时成员及邀请码，核对实际来源搜索、收藏、进度和权限后清理这次创建的数据。它依赖上游接口当时可用，不适合作为无网络环境的构建门禁。`npm test` 无需联网。

## 统一片库与季度首页

- `/` 展示按北京时间当前季度首播的 TV／WEB 动画。名单来自 Bangumi 公共 API，完整读取返回的各页，排除剧场版、OVA、已标记的 MV／广告等；包含本季尚未开播的条目，不包含上一季开始的跨季续播作品。目录和海报标注 Bangumi 来源，缓存 12 小时；刷新失败时仅回退到本季度已有缓存，并明确提示。
- 新番名单独立于播放源覆盖。点击条目会按中文名、原名、年份匹配来源；尚未匹配到播放地址时保留名单，提供片库搜索入口。社区目录可能漏收、延期或更名，名单完整性以该目录当时的收录为准。
- `/catalog` 是独立影视片库。相同规范化片名、年份、内容类别的条目合并为一部作品，语言版本保留为播放项；详情页与播放页可切换来源。不同季数、重制年份不会合并。无法可靠识别的译名差异或上游错误年份仍可能需要人工校正。
- 片库支持类型、年份、国家／地区、题材、上映日期区间、来源与排序，按去重后的作品每页 24 部分页，筛选与页码保存在 URL。只有年份时按全年与日期区间相交来匹配；年份也缺失时不进入日期筛选结果。
- 启动服务后自动逐页建立 SQLite 元数据索引；各来源一轮各取一页，轮次间隔 2 秒，失败等待 60 秒重试，进度持久化。首次完整扫描完成后等待 6 小时开始下一轮。源站更新会使分页内容移动，后续扫描继续补齐；不自动删除失联条目。首次收录期间的统计只代表已收录作品，界面和管理页展示进度。
- 片名搜索会实时补充来源结果到索引并去重。来源搜索仍有后续页时，页面提供“继续检索来源结果”，收录后统一在作品分页中展示，不把上游第一页冒充全部匹配。
- 设置 `CATALOG_SYNC=false` 可停用后台目录同步（实时搜索仍可补充目录）。同步仅适用于当前单实例、持久化 SQLite 部署；不要部署为随请求回收的无状态函数。
